# Reflect

Аналитика для продавцов Kaspi.kz. Reflect собирает продажи, остатки, себестоимость, рекламу и рынок в одно место и отвечает на три вопроса: где я зарабатываю, где теряю и что сделать сегодня. Каждая цифра показывает, откуда она взялась, а оценки помечены как оценки.

## Что умеет

- **Обзор.** Выручка, заказы, прибыль после всех расходов, график по дням и план на день: до шести действий с ожидаемым эффектом.
- **Требует внимания.** Всё, что вышло за пороги:
  - товар закончился или кончится раньше, чем придёт партия;
  - продажи упали, товар в минусе после рекламы, низкая маржа;
  - много возвратов, реклама не окупается;
  - проблемы в данных.
- **Товары.** Разрез по товарам, остатки и количество к заказу, экономика товара по строкам: цена − комиссия − себестоимость − логистика − прочие расходы − реклама. Недостающее можно заполнить прямо там. Блок «Что поправить в данных» показывает пробелы по доле выручки.
- **Реклама и внешние медиа.** Расходы, окупаемость по товарам, замер «до и после» кампаний.
- **Конкуренты.** Продавцы на карточке и карточка на рынке по данным RedStat: ценовые сегменты ниши, ниша по месяцам, лидеры по брендам.
- **Контент.** Проверка карточек товаров.
- **Спросить Reflect.** AI-ассистент отвечает по данным продавца. Если данных ещё нет, он так и говорит, а не отвечает по демо-магазину.
- **Интерфейс** на русском, казахском и английском. Без входа открывается демо-магазин.

## Откуда берутся данные

| Источник | Что даёт | Как подключить |
|---|---|---|
| Kaspi Seller API | заказы и возвраты | токен из кабинета продавца: Настройки → Токен API |
| МойСклад | себестоимость и остатки | токен МоегоСклада |
| RedStat (MCP) | рынок, ниши, конкуренты | адрес MCP-сервера RedStat в настройках |
| Файлы `.csv`, `.xls`, `.xlsx` | заказы, товары, реклама | раздел «Данные»; шаблон скачивается там же |

Синхронизации идут в общей очереди, по умолчанию не больше 4 одновременно (переменная `SYNC_CONCURRENCY`). Прерванная перезапуском сервера синхронизация продолжается сама.

## Попробовать

Нужен компьютер с Docker или GitHub Codespace:

```sh
sh deploy/try-local.sh          # запустить на http://localhost:8080
sh deploy/try-local.sh stop     # остановить, данные сохранятся
sh deploy/try-local.sh reset    # удалить тестовую базу
```

В Codespace адрес открывается на вкладке **Ports**, порт 8080.

## Установка на сервер

Пошаговая инструкция в [DEPLOY.md](DEPLOY.md). Reflect работает в Docker и состоит из четырёх контейнеров:
- приложение;
- PostgreSQL 18;
- Caddy с автоматическим HTTPS;
- ночные бэкапы.

Там же описаны обновление, восстановление из копии, сброс пароля и удаление данных продавца — это делает только администратор.

## Устройство

pnpm-монорепозиторий на TypeScript:

| Папка | Что внутри |
|---|---|
| `artifacts/api-server` | API на Express 5: аналитика, интеграции, импорт, ассистент |
| `artifacts/shift-market` | веб-приложение на React и Vite |
| `lib/api-spec` | OpenAPI-схема, из неё генерируются типы и клиент |
| `lib/api-zod`, `lib/api-client-react` | сгенерированные схемы Zod и хуки React Query |
| `lib/db` | схема базы на Drizzle и версионированные SQL-миграции |
| `deploy` | скрипты установки, обновления, бэкапов и администрирования |

Основная логика расчётов:
- `artifacts/api-server/src/lib/analytics.ts` — показатели, скорость продаж, прибыль, рекомендации;
- `attention.ts` (там же) — пороги для «Требует внимания»;
- `data-quality.ts` (там же) — пробелы в данных.

## Разработка

Нужны Node.js 22 и pnpm 10.

```sh
pnpm install
pnpm run typecheck                                  # проверка типов во всех пакетах
pnpm run test                                       # unit-тесты
pnpm --filter @workspace/scripts run check:i18n     # все тексты есть на трёх языках
pnpm --filter @workspace/api-spec run codegen       # после правки openapi.yaml
pnpm --filter @workspace/db run generate            # после правки схемы: новая миграция
pnpm --filter @workspace/db run migrate             # применить миграции
```

Тесты API на живом сервере с базой:

```sh
TEST_API_URL=http://localhost:8080/api pnpm --filter @workspace/api-server run test
```

Браузерные тесты (Playwright). Поддельные Kaspi и RedStat позволяют проверить подключение без настоящего магазина:

```sh
node artifacts/shift-market/e2e/fake-kaspi.mjs 8099 &
node artifacts/shift-market/e2e/fake-redstat.mjs 8098 &
# API запущен с KASPI_API_BASE=http://127.0.0.1:8099/shop/api/v2 и MCP_ALLOW_PRIVATE=1
FAKE_KASPI=1 FAKE_REDSTAT=1 SHIFT_MARKET_TEST_BASE_URL=http://localhost:8080 \
  pnpm --filter @workspace/shift-market run test:e2e
```

Переменные окружения описаны в [`.env.example`](.env.example). Главные:
- `DATABASE_URL` — без неё Reflect работает только как демо;
- `ENCRYPTION_KEY` — шифрует токены интеграций; в production без него API не запускается;
- `ANTHROPIC_API_KEY` — для ассистента;
- `SMTP_URL` — для писем о сбросе пароля.

## Как вносить изменения

- Каждое изменение делается в отдельной ветке и попадает в `main` через pull request. Прямые пуши в `main` закрыты.
- Pull request можно смёрджить, только когда прошли все четыре проверки CI:
  - типы, переводы, unit-тесты и сборка;
  - тесты API с PostgreSQL;
  - развёртывание в Docker со скриптами бэкапов и администрирования;
  - браузерные тесты.
- Изменение схемы базы — только новой миграцией в `lib/db/migrations`, без правки старых.
